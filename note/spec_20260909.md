## 1. 機能A：調査対象店舗選択ポップアップ（`CvsStoreWidget.StoreSelect`）

### 1-1. 起動 `open(arg)`

| 引数の型 | 解釈 |
|---|---|
| 文字列 / 数値 | `{ file: arg }` として扱う |
| オブジェクト | `{ file, rec_id, storeId, title, width, height, dialogOptions }` |

- `file` … 関連ファイルのID/名（任意）。新規店舗登録リクエストに乗せる。
- `rec_id` … 投稿済み画像のID（任意）。新規店舗登録リクエストに乗せる。
- `storeId`（別名 `id_cvs_store`）… その店舗を選択済みの状態で開く。前回 `store-selected` の
  payload をそのまま渡してもよい。
- `title` / `width` / `height` / `dialogOptions` … jQuery UI dialog オプションをその場で上書き。

`open()` の流れ:
1. `resetForm()`（入力欄・選択状態を全クリア。`submitting=false`、OKボタン有効化）
2. `currentFile` / `currentRecId` を引数から保持
3. `applyDialogOptions()`（title/width/height/dialogOptions を反映）
4. `loadOptionsIfNeeded()`（初回のみ選択肢APIを取得。後述）→ そのコールバックで
   - `renderFavorites()`（お気に入りチップ描画）
   - `storeId` があれば `preselectById()` → 完了後に `dialog('open')`。無ければそのまま `dialog('open')`
5. dialog の `open` コールバックで店舗名入力欄にフォーカス

### 1-2. 表示（jQuery UI dialog）

- `modal: true` / `width: 480` / `appendTo: 'body'` / `autoOpen: false` / `closeText: '閉じる'`
- タイトル … ルート要素 `#storeSelectDialog` の `title` 属性（既定「店舗選択」）。`open({title})` で上書き可
- ボタン … `OK`（class `cvs-dialog-confirm`）/ `Cancel`
- 閉じる操作 … `Cancel` ボタン / タイトルバーの × / ESC キー（`closeOnEscape` 既定）。**暗幕クリックでは閉じない**（jQuery UI 既定）
- `close` 時にサジェスト候補を閉じる

### 1-3. 画面項目（フラグメント `storeSelectPopup` の中身）

| 項目 | 要素 | 必須 | 補足 |
|---|---|---|---|
| お気に入り店舗 | チップ（`<button class="cvs-favorite-chip">`）の一覧 | - | 0件なら「お気に入り店舗が登録されていません。」 |
| 店舗名 | `#storeNameInput`（text）＋ サジェスト `#suggestList` | ○ | 未登録店舗名も入力可。hidden `#selectedStoreId` に選択店舗IDを保持 |
| （新規店舗ヒント）| `#newStoreHint` | - | 「店舗マスタに未登録の店舗として扱われます。…」 |
| チェーン名 | `#chainSelect`（select） | ○ | 選択肢はAPI取得 |
| 立地条件 | `#locationSelect`（select） | ○ | 同上 |
| 都道府県 | `#prefectureSelect`（select） | ○ | 同上 |
| エラーメッセージ | `#formErrorMessage` | - | 必須未入力／登録失敗時に表示 |

### 1-4. 選択肢の取得（`loadOptionsIfNeeded`）

- **ポップアップを初めて開いたとき1回だけ** `$.when()` で3本を並行取得:
  `POST /api/cvs_chains` `POST /api/cvs_locations` `POST /api/regions`（いずれも body は空JSON `{}`）
- レスポンスは `{ records: [ ... ] }`。`records` を各 `<select>` の `<option>` に流し込む
  （value = コード、text = 名称）
- 取得済みフラグ `optionsLoaded` により2回目以降は再取得しない
- **失敗時のハンドリングなし**（`.fail` を持たない）。3本のどれかが失敗するとコールバックが
  走らず、ダイアログが開かない・無言になる（既知の弱点）

### 1-5. お気に入りチップ

- `FavoritesUtil.getNames()`（cookie `favoriteStores`、店舗名の配列）を描画
- チップクリック → `selectFavorite(name)`:
  1. 店舗名欄に `name` をセット
  2. `GET /api/stores/search?q=name` を実行し、`nm_cvs_store === name` の完全一致を抽出
  3. 完全一致 **1件** → `applyStore()`（選択確定）
  4. 完全一致 **複数件** → サジェスト候補リストにその複数店舗を表示し選び直させる
     （店舗名にチェーン名を含めないため別チェーンに同名店舗があると起きる）
  5. 完全一致 **0件** → 選択なし（`appliedStore=null`）。店舗名だけ入った状態＝新規店舗扱い

### 1-6. 店舗名サジェスト（`StoreSuggest`）

- 入力するたびに `GET /api/stores/search?q=<入力値>`（**デバウンス 300ms**）
- **IME変換中は検索しない**（`compositionend` で1回だけ実行）
- 入力欄が空になったら候補を閉じる
- **フォーカスを外して戻ったとき**、値があれば即再検索（デバウンス無し）。
  ただし「確定済みの選択と現在値が一致」している場合は再表示しない（`isResolved`）
- 候補リストは `position: fixed`（viewport 基準）。入力欄の実座標から位置・幅を算出し、
  下に入り切らず上の方が広ければ上向きに開く。表示中はスクロール／リサイズに追従
- 候補の外側をクリックすると閉じる
- 候補 **0件** → 「該当する店舗がありません（新規店舗として登録できます）」
- 候補クリック → `applyStore(store)`

### 1-7. `applyStore(store)`（選択確定）

- `appliedStore = store`
- 店舗名欄 = `nm_cvs_store` / hidden = `id_cvs_store` / 3つの `<select>` = `cd_cvs_chain` `cd_cvs_location` `cd_region`
- 新規店舗ヒントを再判定

### 1-8. 新規店舗ヒント（`refreshNewStoreHint`）

- 店舗名が入力されていて、かつ「既存店舗と完全一致でない」ときに `#newStoreHint` を表示
- 「完全一致」の判定（`isExistingStore`）= `appliedStore` があり、かつ
  **店舗名 ＋ チェーンコード ＋ 立地コード ＋ 都道府県コード がすべて一致**
- チェーン/立地/都道府県の `<select>` を変更するたびに再判定

### 1-9. 前回店舗の事前選択（`open({ storeId })`）

- `GET /api/stores/search?id=<storeId>` で1件取得 → 見つかれば `applyStore()`
- 見つからない／通信失敗 → **空のまま開く**（`console.warn` のみ、利用者には見せない）
- いずれの場合もダイアログは開く

### 1-10. OK 押下（`handleConfirm`）

1. `submitting` 中なら何もしない（二重実行防止）
2. **必須チェック**（店舗名・チェーン・立地・都道府県のいずれか未入力）
   → `#formErrorMessage` に「店舗名・チェーン名・立地条件・都道府県はすべて必須です。」。閉じない
3. **既存店舗**（`isExistingStore` = true）
   → 登録APIを呼ばず、ダイアログを閉じて `store-selected` を発火
   （payload = 現在値 ＋ `id_cvs_store`（`appliedStore.id_cvs_store`））
4. **新規店舗**
   1. `window.confirm('新規店舗として登録しますか？')`（ネイティブ確認）
      - キャンセル → 何もしない（ダイアログはそのまま）
   2. OK → `PUT /api/stores`（body 下記）。`submitting=true` ＋ OKボタン無効化（二重登録防止）
      - **成功** → `submitting=false`、ダイアログを閉じ、`store-selected` を発火
        （payload = 現在値に `response.records` を上書きマージしたもの。採番済み `id_cvs_store` を含む）
      - **失敗** → `submitting=false`、OKボタン再有効化、`#formErrorMessage` に
        「登録に失敗しました。時間をおいて再度お試しください。」

PUT リクエスト body（新規店舗）:

```
id_cvs_store  : null（サーバー採番）
nm_cvs_store  : 店舗名
cd_cvs_chain / nm_cvs_chain
cd_cvs_location / nm_cvs_location
cd_region / nm_region
file          : open() の file（未指定 null）
rec_id        : open() の rec_id（未指定 null）
user_id       : config.userId、無ければ cookie（config.userIdCookie 既定 'initNoEmp'）、無ければ null
```

### 1-11. `store-selected` イベント payload

```js
$(document).on('store-selected', function (e, store) {
  // store = {
  //   id_cvs_store,         // 既存店舗は選択店舗のID / 新規はサーバー採番ID
  //   nm_cvs_store,
  //   cd_cvs_chain, nm_cvs_chain,
  //   cd_cvs_location, nm_cvs_location,
  //   cd_region, nm_region,
  //   file, rec_id, user_id // 新規登録時のみ（response.records 経由で入る）
  // }
});
```

### 1-12. 再オープン時の挙動

- `open()` の先頭で必ず `resetForm()` が走る → 何も渡さなければ**毎回まっさら**
- `open({ storeId })` を渡したときだけ前回店舗を復元

## 2. 機能B：お気に入り店舗名の入力欄（`CvsStoreWidget.FavoriteEdit`）

### 2-1. 形態

- **単独ポップアップではない。** 社内アプリの既存ダイアログ（jQuery UI dialog）の中身テンプレートへ
  フラグメント `favoriteEditFields`（`class="cvs-store-widget"` のラッパ ＋ `<div data-cvs-favorite-edit-rows>`）を
  `th:replace` で埋め込み、JS で下記メソッドをダイアログのライフサイクルに配線する。

### 2-2. 公開API

| メソッド | 役割 | 呼びどころ |
|---|---|---|
| `mount(target?, options?)` | `target`（省略時 `[data-cvs-favorite-edit-rows]`）に入力行を生成。`options.count` で行数（既定 `FavoritesUtil.MAX_COUNT` = 10）。冪等（呼ぶたび作り直す） | ページ初期化時に1回 |
| `load()` | cookie `favoriteStores` から各入力欄を復元。`mount` 前に呼ぶと警告のみ | ダイアログの `dialogopen` イベント |
| `save()` | 入力値を保存（後述ルール）→ cookie 書き込み → `favorites-updated` を発火 → 保存後配列を返す | 既存の「保存」処理の中 |
| `getValues()` | 現在の入力値（trim 済み・行数ぶんの配列。空文字・重複を含みうる）。保存しない | 任意 |
| `reset()` | 全行のサジェスト候補を閉じる | ダイアログの `dialogclose` イベント |

- `mount()` は既存ダイアログの `dialog({...})` 定義には手を入れず、
  `$('#dlg').on('dialogopen', …).on('dialogclose', …)` と保存ハンドラ内 `save()` で配線する
  （`open`/`close` はコールバックが1個しか持てず既存処理を上書きするため）。

### 2-3. 入力行

- 各行 = 「N.」ラベル（列幅 20px 固定・`layout.css`）＋ テキスト入力（id `cvs-favorite-input-{0..9}`）＋ サジェスト
- サジェストは機能Aと同一の `StoreSuggest`（IME対応・デバウンス300ms・フォーカスバック再表示・
  確定済みは再表示しない）
- placeholder「店舗名を入力してください」

### 2-4. 保存ルール（`save()` → `FavoritesUtil.saveNames`）

- 各行の値を trim
- 空文字の行は保存しない
- 重複する店舗名は排除（先勝ち）
- 先頭 **10件** まで（超過分は切り捨て）
- cookie `favoriteStores`（JSON配列、`path=/`、有効30日）へ書き込み
- `favorites-updated` イベントに保存後の配列を渡して発火

### 2-5. `favorites-updated` イベント

```js
$(document).on('favorites-updated', function (e, savedNames) {
  // savedNames: 保存された店舗名の配列（trim・重複排除済み・最大10件）
});
```

## 3. データ・API 仕様（モック）

### store オブジェクト

`{ id_cvs_store:number, nm_cvs_store:string, cd_cvs_chain:string, nm_cvs_chain:string,
cd_cvs_location:string, nm_cvs_location:string, cd_region:string, nm_region:string }`
※コード値（`cd_*`）は**文字列型**。店舗名（`nm_cvs_store`）にチェーン名は含めない。

### エンドポイント

| メソッド | パス | リクエスト | レスポンス |
|---|---|---|---|
| GET | `/api/stores/search?q=<文字列>` | - | store 配列（`nm_cvs_store LIKE '%q%'`、最大20件、0件は `[]`） |
| GET | `/api/stores/search?id=<id_cvs_store>` | - | 完全一致 store 1件の配列（`q` は無視、0件は `[]`） |
| POST | `/api/cvs_chains` | body `{}` | `{ records: [ {cd_cvs_chain, nm_cvs_chain}, ... ] }` |
| POST | `/api/cvs_locations` | body `{}` | `{ records: [ {cd_cvs_location, nm_cvs_location}, ... ] }` |
| POST | `/api/regions` | body `{}` | `{ records: [ {cd_region, nm_region}, ... ] }` |
| PUT | `/api/stores` | 1-10 の body | `{ records: { …店舗1件（採番済み id_cvs_store 含む）… } }`。必須欠落は `400 { success:false, message }` |

- 全パスは `config.contextPath` を `apiUrl()` が前置（モックは `''`）。
- モックの新規登録店舗はインメモリ（`registeredTargets`）にのみ保持。`?id=` 検索は
  `STORES`（マスタ）＋ `registeredTargets` を対象にする。
- `config.API_MODE = 'production'` の場合、Express が社内本番APIへ Cookie 付きでプロキシ
  （`?q=` `?id=` もそのまま透過）。

### モックのテストデータ（`data/stores.js`）

- 店舗マスタ 29件（`id_cvs_store` 1〜29）。
- **同名店舗**: 「渋谷駅前店」= `id:1`（セブンイレブン）と `id:29`（ローソン）
  → お気に入り「渋谷駅前店」クリック時に複数候補が出るケースの確認用。
- チェーン6 / 立地条件6 / 都道府県47。

## 4. 既知の制約・仕様上の注意

- 選択肢API（`/api/cvs_chains` ほか3本）の**失敗ハンドリングが無い**。1本でも失敗すると
  ポップアップが開かず無言になる。
- 新規店舗登録の確認は `window.confirm`（ネイティブ）。
- 店舗選択ダイアログのキャンセルボタンのラベルは英語表記「Cancel」。
- `favoriteEditFields` フラグメントのヒント文は現状「お気に入り店舗名： 」（デモの
  `index.html` 側は別文言）。
- お気に入り cookie は `favoriteStores`（`path=/`）。名前空間・スコープは組み込み時に要検討。
- CSRF 未対応（社内で Spring Security 有効なら非GET＝マスタ取得POST・登録PUTが403）。
- 登録APIの `PUT /api/stores` は非冪等（呼ぶたび新規店舗が作られる）。二重送信は
  `submitting` フラグ＋OKボタン無効化で抑止。
