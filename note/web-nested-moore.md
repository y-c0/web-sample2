# 調査対象店舗選択ポップアップ + モックサーバ 実装計画

## Context
コンビニ店舗調査結果を登録するWebアプリに、「調査対象の店舗を選ぶ」ポップアップ画面を新設する。投稿者は
- 店舗マスタに既に存在する店舗を検索して選ぶ
- 店舗マスタに無い任意の店舗名を新規入力する
- Cookieに保持された「お気に入り店舗」から選ぶ

のいずれかで対象店舗を指定できる必要がある。作業ディレクトリは空で既存コードが無いため、今回はモックサーバ（Express）とフロントエンド一式をこのディレクトリにゼロから新規構築する。既存本番アプリは素のHTML/CSS + jQuery 1.7.2構成のため、それに合わせて実装する（React/Vue等のフレームワークは使わない）。

## 全体構成
```
20260817_simple/
├── package.json
├── server.js               … Expressモックサーバ（静的配信 + API）
├── data/
│   └── stores.js            … 店舗マスタのダミーデータ（配列）とチェーン名/立地条件/都道府県の選択肢
└── public/
    ├── index.html            … ホスト画面（既存アプリの1画面を模したデモ。「調査対象店舗を選ぶ」ボタンからポップアップを開く）
    ├── css/style.css         … ポップアップ/ホスト画面の見た目
    ├── js/jquery-1.7.2.min.js … 既存アプリと同じバージョンのjQuery（CDNではなくローカル配置し既存構成に合わせる）
    ├── js/main.js            … ホスト画面側ロジック（ポップアップ起動、選択結果の受け取り、お気に入りCookieのテスト用シード機能）
    └── js/store-select.js    … ポップアップ本体のロジック（サジェスト検索、選択肢反映、お気に入り表示、登録）
```

## データモデル（モック）
`data/stores.js` に以下を用意する。

- 店舗マスタ配列（20〜30件程度、サジェストのテストがしやすいよう同一チェーン・類似名を複数含める）
  - `id`, `storeName`(nm_cvs_store相当), `chainName`, `locationType`, `prefecture`
- 選択肢マスタ
  - チェーン名一覧（セブンイレブン/ファミリーマート/ローソン/ミニストップ/デイリーヤマザキ 等）
  - 立地条件一覧（駅前/繁華街/郊外/住宅街/オフィス街/ロードサイド 等）
  - 都道府県一覧（47都道府県）

## モックAPI（Express, server.js）
1. `GET /api/stores/suggest?q=xxx`
   - `nm_cvs_store LIKE '%xxx%'` 相当で `storeName.includes(q)` フィルタ（大文字小文字/全角半角の簡易正規化程度に留め、複雑な曖昧検索はしない）
   - 一致した店舗を `id, storeName, chainName, locationType, prefecture` の配列で返す（最大20件）
   - `q` が空なら空配列を返す
2. `GET /api/options`
   - `{ chains: [...], locations: [...], prefectures: [...] }` をまとめて返す（画面初期表示時に1回呼ぶ）
3. `POST /api/target-store/register`
   - body: `{ id: number|null, storeName, chainName, locationType, prefecture }`
   - サーバ側はインメモリ配列にpush＆console.logするだけのモック。`{ success: true, id }` を返す

## ポップアップ画面（public/index.html 内にモーダルとして実装）
「ポップアップ」は別ウィンドウではなく、既存アプリ内のモーダルダイアログとして実装する（jQuery 1.7.2世代のUIとして自然で、テストもしやすいため）。

### 項目
- 店舗名入力欄（テキスト）
  - `keyup` を約300msデバウンスして `/api/stores/suggest` をAjax呼び出し
  - 結果を入力欄直下のドロップダウンリストに表示（店舗名 + チェーン名 + 都道府県を併記して見分けやすくする）
  - 候補クリックで選択 → 店舗名・チェーン名・立地条件・都道府県欄に反映し、内部で `selectedStoreId` を保持
  - 該当なしの場合は「該当する店舗がありません（新規店舗として登録できます）」を表示
  - 店舗名を選択後に手入力で変更した場合は `selectedStoreId` をクリアし、以後は「店舗マスタ未登録の任意店舗」として扱う（チェーン名等は自由入力のまま残す＝手直しの手間を減らす）
- チェーン名 / 立地条件 / 都道府県（`<select>`）
  - `/api/options` の結果で初期化。先頭は「選択してください」
  - 店舗名サジェスト候補選択時・お気に入り選択時に自動セットされるが、その後もユーザーが手動で変更可能（任意店舗登録に対応するため常に編集可）
- お気に入り店舗
  - Cookie（例: `favoriteStores`、店舗名のJSON配列、最大10件）から読み込み、チップ/ボタン一覧として表示
  - クリックすると店舗名欄にセットし、`/api/stores/suggest` に完全一致相当のクエリを投げてチェーン名等を取得・反映（一致しない場合は店舗名のみ入力し他欄は手動選択を促す）
  - Cookieは本来「他画面」が設定する前提のため、このモックでは `public/js/main.js` に検証用のシードボタン（サンプルのお気に入り名をCookieにセットする）を用意する
- 「決定」ボタン
  - 店舗名必須・チェーン名/立地条件/都道府県必須のバリデーション後、`POST /api/target-store/register` を実行
  - 成功したらモーダルを閉じ、選択結果を `document` に対して `store-selected` カスタムイベント（`detail`に選択店舗情報）でホスト画面に通知 → `main.js` が受け取り画面上に表示する。実アプリ統合時はこのイベントを購読して次画面遷移や登録に使う想定
- 「キャンセル」ボタン：何もせずモーダルを閉じる

## 検証方法
1. `npm install` → `node server.js`（または `npm start`）でモックサーバ起動
2. ブラウザで `http://localhost:3000` を開く
3. 「お気に入りサンプルをセット」→ ページ再読込 → ポップアップを開き、お気に入りから選択できることを確認
4. 店舗名入力でサジェストが動くこと（部分一致で複数候補、チェーン名・立地条件・都道府県欄が自動反映されること）を確認
5. マスタに無い店舗名を入力し、チェーン名等を手動選択して「決定」→ 登録APIが呼ばれ、ホスト画面に選択結果が表示されることを確認
6. サーバ側コンソールで `POST /api/target-store/register` のログが出力されることを確認
